# 分阶段重构计划

## 禁止事项与执行前提

- 不顺手重命名；不格式化无关文件；不改现有公共 API 的名称、签名或序列化字段；不在一个 PR 混合多个主题。
- 核心逻辑没有针对性回归测试之前，不改变其行为。每阶段先添加能复现边界的测试，再修改实现。
- 每阶段最多修改或新增 10 个文件；超过上限就拆 PR，不通过“顺手整理”扩容。
- 每阶段独立分支、独立 PR、独立提交和回滚。合并前后均运行 `pwsh -File .\dev.ps1 check`；失败时不带着失败进入下一阶段。
- 单阶段在下一阶段启动前可单独回滚；若已有依赖它的后续阶段合并，必须按依赖逆序回滚，不能只撤掉底层契约。
- 当前工作区有尚未提交的 0.3 功能改动。执行 R01 前，先将功能改动单独提交到明确的基线分支，或隔离到另一工作树；不得把它们混入任何重构 PR。
- `docs/audit.md` 目前未在仓库中落盘。下文审计编号对应上一轮只读审计全文；若要在 PR 中使用文档链接，应先单独保存审计文档，不计入任何重构阶段。

文件数统计包含新增测试、辅助类和项目文件。每阶段的“修改范围”是允许触碰的上限，而不是要求全部修改；清单之外的改动应另开阶段。下述验收命令均在仓库根目录、PowerShell 7 中执行。

## R01：固定测试发现与用例数

- **目标**：去掉按源文件是否存在而改变测试数量的机制，让当前功能基线的测试集合固定、失败即返回非零退出码。
- **背景**：P1-06、P2-11。当前 `tests/Baseline.Tests.ps1` 通过检查 `StartupService.cs` 是否存在来决定是否运行用例。
- **修改范围（最多 3 个文件）**：`dev.ps1`、`tests/Baseline.Tests.ps1`、新增 `tests/TestDiscovery.Tests.ps1`。
- **具体步骤**：先写用例证明“缺少期望的启动模块时测试失败”；让 `dev.ps1 test` 发现所有 `*.Tests.ps1` 并核对预期用例标识及精确数量；将启动 XML 测试从条件分支改为显式必跑用例。保持现有 `test` 命令入口。
- **验收命令**：`pwsh -File .\dev.ps1 test`；`pwsh -File .\dev.ps1 check`。两者退出码均为 0，测试数量固定；临时移除测试目标的负向检查必须失败。
- **风险**：低。
- **回滚方式**：仅回滚本 PR；恢复原测试发现脚本后重新运行 `check`，不涉及用户数据。
- **完成标准**：同一源码基线连续两次运行得到相同用例数；缺失必测模块不再被当作“少运行一项但仍通过”。
- **本阶段不做**：不新增配置、网络或 UI 行为测试；不改任何应用业务代码。

## R02：构建源码清单一致性

- **目标**：使脚本构建与 `.csproj` 编译相同的 C# 文件，防止新增文件只进入一条构建路径。
- **背景**：P2-12、P2-15。
- **修改范围（最多 4 个文件）**：`build.ps1`、`DesktopCountdown.csproj`、`dev.ps1`、新增 `tests/BuildInventory.Tests.ps1`。
- **具体步骤**：先加入故意遗漏一个源文件时会失败的清单测试；选定 `.csproj` 的 `Compile Include` 为唯一清单，让构建脚本解析该清单并检查文件存在及重复项；保留现有 `build.ps1` 参数与产物路径。
- **验收命令**：`pwsh -File .\dev.ps1 lint`；`pwsh -File .\dev.ps1 check`。清单不一致的负向用例必须失败。
- **风险**：低。
- **回滚方式**：回滚本 PR 即恢复原构建清单逻辑；对比回滚前后的源码列表，不触碰生成产物以外的文件。
- **完成标准**：两个构建入口使用或校验同一源码集合，新增 `.cs` 时漏改项目文件可被门禁拦截。
- **本阶段不做**：不升级 .NET、引入 NuGet/SDK 风格项目或全仓自动格式化。

- **完成标准**：`AppSettings.cs` 不再出现 `ThemeCatalog`、`DisplayFormats`、`MotionPlanner` 引用；默认配置和公开常量保持原值。

- **本阶段不做**：不调整登录启动、设置 UI 布局或配置字段名称。
